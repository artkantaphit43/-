# เหตุผลการออกแบบ (Design rationale)

เอกสารนี้อธิบาย *ทำไม* ปลั๊กอินถึงทำงานแบบนี้ – เพื่อให้ผู้ใช้ตรวจสอบได้ว่าผลลัพธ์น่าเชื่อถือแค่ไหน
และเพื่อให้ผู้พัฒนาต่อยอดได้ถูกทาง

## 1. สถาปัตยกรรม: แยก "แกนวิศวกรรม" ออกจาก SketchUp

| ชั้น | ที่อยู่ | หน้าที่ |
|---|---|---|
| แกนคำนวณ | `lib/` | มาตรฐานท่อ, ไฮดรอลิก, เรขาคณิตข้อต่อ, BOM, ตรวจชน – Ruby ล้วน หน่วย mm |
| ตัวเชื่อม SketchUp | `su/` | สร้าง geometry, เครื่องมือวาด, หน้าต่าง, แปลงหน่วย mm ↔ inch |

**เหตุผล:** ส่วนที่ผิดพลาดแล้วเสียหายที่สุดคือ *ตัวเลข* (ขนาดท่อ ความยาว การคำนวณ) ไม่ใช่รูปทรง
การแยกทำให้ทดสอบตัวเลขได้อัตโนมัติโดยไม่ต้องเปิด SketchUp (68 tests: ตรวจกับค่าตารางมาตรฐาน,
คำนวณมือ, และสมการ Colebrook) และมี stub ของ SketchUp API เพื่อทดสอบขั้นตอนสร้างโมเดลทั้งหมด

## 2. แนวท่อ (Run) คือ "ข้อมูล" ไม่ใช่แค่รูปทรง

แต่ละแนวท่อเก็บ *เส้นศูนย์กลาง*, *จุดเชื่อม Tee*, และ *ค่าตั้ง* ไว้ใน attribute แล้วสร้างรูปทรงจากข้อมูลนั้น

**เหตุผล:** งานออกแบบระบบท่อต้องแก้ขนาดบ่อย (หลังคำนวณไฮดรอลิก, หลัง value engineering)
ถ้าต้องวาดใหม่ทุกครั้งจะเสียเวลาและผิดพลาดง่าย → คำสั่ง *ปรับท่อที่เลือก* สร้างใหม่ทั้งแนวในคลิกเดียว
วาล์วคงตำแหน่งเดิม และ Tee ของท่อแยกที่ต่ออยู่ปรับขนาดตาม (Reducing Tee ถูกต้องใน BOM)

## 3. เรขาคณิตข้อต่อ (`lib/network.rb`)

- จุดที่ห่างกัน ≤ 1 mm ถือเป็นจุดเดียว (เส้นจาก CAD มักคลาดเล็กน้อย)
- ชนิดข้อต่อดูจาก *จำนวนแขน* และ *มุม*: 2 แขน = ข้องอ, 3 แขน = Tee (90°) หรือ Lateral/Wye (มุมอื่น), 4 แขน = Cross
- ข้องอกินความยาวท่อ T = R·tan(θ/2) (R ตาม ASME B16.9) – ความยาวท่อใน BOM จึงเป็น *ความยาวท่อจริง* ไม่ใช่ความยาวเส้นศูนย์กลาง
- **ถ้าท่อตรงระหว่างข้องอสั้นเกินไป** ระบบลดจาก Long Radius → Short Radius → รอยต่อเฉียง (mitre)
  พร้อมแจ้งเตือน – เป็นการตัดสินใจแบบเดียวกับที่ผู้ออกแบบท่อทำ และไม่สร้างรูปทรงที่ผิดหรือซ้อนกัน

## 4. ช่วยการวาดให้ถูกหลักงานท่อ

| สิ่งที่ทำ | เหตุผล |
|---|---|
| ล็อกทิศ 45°/90° ในแปลน, ท่อยืนตั้งฉาก | ข้อต่อมาตรฐานมีแค่ 90°/45° – มุมอื่นต้องตัดข้อต่อหรือดัดท่อ (แพงและผิดสเปก) ยกเว้นเมื่อ snap ไปยังจุดของวัตถุจริง |
| ท่อระบายลาดเองตามทิศที่วาด | ทำให้ "ทิศการวาด = ทิศการไหล" เป็นนิสัย และความลาดไม่ต่ำกว่าเกณฑ์ IPC |
| พิมพ์ความยาวท่อระบาย = ความยาวในแปลน | แบบก่อสร้างระบุระยะในแปลน ความลาดเป็นผลตามมา |
| อ้างอิง BOP | ท่อบนรางท่อ/คานกำหนดระดับที่ท้องท่อ (Bottom of Pipe) ไม่ใช่ศูนย์กลาง |
| วาล์ววางบนท่อตรงเท่านั้น, ก้านชี้ขึ้น | วาล์วใส่ในข้อต่อไม่ได้, ก้านชี้ลงทำให้ของเหลวรั่วใส่ผู้ปฏิบัติงานและตะกอนสะสมที่ bonnet |
| Butterfly ≥ 6" ใช้ gear operator | แรงบิดสูงเกินกว่าจะใช้ lever อย่างปลอดภัย |

## 5. การคำนวณ – เลือกวิธีที่ "ถูกกับของไหล"

- **Darcy–Weisbach** เป็นหลักสำหรับของเหลว เพราะ Hazen–Williams ถูกปรับเทียบกับน้ำเย็นเท่านั้น (ใช้กับน้ำร้อน/น้ำมันจะผิด)
- **Hazen–Williams** แสดงเพิ่มสำหรับท่อดับเพลิง เพราะ NFPA 13 กำหนดให้ใช้
- **ก๊าซ/ไอน้ำ/ลม** ตรวจความเร็วอย่างเดียว – การคำนวณความดันตกต้องรู้ความดันและความหนาแน่นตลอดเส้น
  ซึ่งเครื่องมือวาดแบบไม่ควร "เดา" ให้
- **ท่อระบาย** ใช้ Manning ที่ความลึกครึ่งท่อ (เผื่อทางระบายอากาศในท่อ) และความเร็วชำระล้าง ≥ 0.6 m/s
- ค่าเกณฑ์ (v max, hf max) เป็น *แนวทางออกแบบ* ที่ใช้กันทั่วไป ไม่ใช่ข้อบังคับ – แสดงไว้ให้เห็นเสมอ

### จุดสูง/จุดต่ำ (`lib/profile.rb`)

วิเคราะห์จากโครงข่ายเส้นศูนย์กลาง *ไม่ขึ้นกับทิศทางที่วาด*: กลุ่มจุดระดับเดียวกันที่ทุกท่อที่ออกไปขึ้นสูง = จุดต่ำ,
ลงต่ำทั้งหมด = จุดสูง (ยกเว้นกลุ่มที่มีปลายเปิด ซึ่งระบาย/ไล่อากาศผ่านอุปกรณ์ได้)
แล้วแนะนำอุปกรณ์ตามชนิดของไหล – เป็นรายการตรวจสอบที่มักถูกลืมในแบบจริง

## 6. ตรวจการชนกัน (`lib/clash.rb`)

- แทนชิ้นส่วนด้วย "แคปซูล" (เส้นตรง + รัศมี): ท่อ, แขน Tee, คอร์ดของข้องอ, วาล์วใช้รัศมีหน้าแปลน
- **รวมความหนาฉนวน** เพราะสิ่งที่ชนกันหน้างานคือผิวฉนวน
- ไม่เทียบชิ้นส่วนในแนวท่อเดียวกัน และยกเว้นบริเวณจุดเชื่อมที่ตั้งใจ (Tee แยก, ต่อปลายชนปลาย)
- ใช้ sweep-and-prune ตามแกน X จึงรองรับโมเดลโรงงานขนาดใหญ่ได้

## 7. BOM เพื่อการจัดซื้อ

- ท่อแสดงทั้งความยาวและ **จำนวนท่อน** (ท่อน 6 m เหล็ก / 4 m พลาสติก + เผื่อเศษตัด) เพราะผู้ขายขายเป็นท่อน
- น้ำหนัก = π·t·(OD−t)·ρ (สำหรับเหล็ก = 0.02466·t·(OD−t) kg/m) – ใช้ประเมินค่าขนส่งและน้ำหนักบน support
- จำนวนรอยต่อโดยประมาณ ใช้ประเมินค่าแรงเชื่อม/ต่อท่อ
- CSV เป็น UTF-8 พร้อม BOM และ CRLF → Excel ภาษาไทยบน Windows เปิดได้ไม่เป็นภาษาต่างดาว

## 8. ความซื่อตรงของข้อมูล

ค่าที่ไม่ได้มาจากตารางมาตรฐานโดยตรงถูกระบุชัด:
- ความหนาท่อ PVC มอก.17 = ค่าประมาณ (มีคำเตือนใน UI และหมายเหตุใน BOM)
- ขนาดข้อต่อพลาสติก/เกลียว และรูปทรงตัววาล์ว = สัดส่วนโดยประมาณสำหรับการจัดวาง
- ค่า K ของข้อต่อ = ค่าทั่วไป (Crane TP-410) ไม่ใช่ค่าของผู้ผลิตเฉพาะ

ผู้ใช้เพิ่มแค็ตตาล็อกของผู้ผลิตจริงได้ผ่าน `custom_catalog.json`

## 9. แนวคิดต่อยอด (Roadmap)

1. **Reducer / Eccentric reducer แบบ inline** – ท่อดูดปั๊มต้องใช้ eccentric reducer แบบ flat-on-top
2. **Pipe support อัตโนมัติ** – วางจุดรองรับตามระยะห่างสูงสุด (เช่น MSS SP-58/69) และคำนวณน้ำหนักลงจุดรองรับ (มีน้ำหนักท่อ+น้ำแล้ว)
3. **แบบ Isometric / Spool drawing** – ส่งออกข้อมูลเส้นศูนย์กลาง + ข้อต่อเป็น PCF สำหรับ Isogen
4. **Fixture Units (WSFU/DFU)** – คำนวณอัตราไหลน้ำประปาและน้ำทิ้งจากสุขภัณฑ์ (Hunter's curve) สำหรับอาคารในโรงงาน
5. **Hydraulic network solver** – คำนวณการกระจายการไหลในระบบวงแหวน (loop) เช่น fire ring main (Hardy Cross)
6. **Slope annotation และ invert level** อัตโนมัติสำหรับท่อระบาย
7. **เชื่อมกับ P&ID** – นำเข้ารายการ Line list (CSV) เพื่อกำหนดขนาด/ระบบให้แต่ละแนวท่อ
